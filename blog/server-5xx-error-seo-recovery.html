SEO対策 2026.10.24 読了時間：11分

サーバー5xxエラーの原因と対処完全ガイド｜SEOへの影響と緊急復旧手順【2026年版】

サーバー5xxエラー(500/502/503/504)は、SEOと売上の両方に深刻なダメージを与えます。この記事では各エラーの原因・緊急復旧手順・SEOへの影響・再発防止策を、Cloudflare・Vercel・CORESERVERなど主要ホスティング別の対処法まで、個人事業主・小規模店舗の運営者が自力で復旧できるレベルで徹底解説します【2026年版】。

TL;DR — この記事の要点

5xxエラーは『サーバー側の問題』。500=内部エラー、502=上流サーバー不通、503=過負荷、504=タイムアウト。Googleは24-48時間連続で5xxだとクロール頻度を落とし、長期化で順位急落。即復旧→Search Console確認が鉄則。

5xxエラーの種類と各原因

500 Internal Server Error

サーバー内部の処理エラー。プログラムのバグ・PHP構文エラー・権限不足が主原因。

502 Bad Gateway

プロキシ/ロードバランサーが上流サーバーから無効な応答を受け取った状態。バックエンドサーバーが落ちていることを意味。

503 Service Unavailable

サーバーが過負荷・メンテナンス中で応答不能。アクセス集中・DDoS攻撃の可能性。

504 Gateway Timeout

上流サーバーからの応答が指定時間内に返らなかった状態。処理時間が長すぎるクエリ・外部API遅延が原因。

5xxエラーのSEOへの影響

Googlebotは5xxエラーを『サーバー問題で一時的』と判断しますが、長期化するとSEOに深刻な影響が出ます。

時間経過別の影響

  • 数時間〜1日:クロール頻度が一時的に低下。順位への影響はほぼなし
  • 24-48時間:クロール頻度が大幅低下。新規ページのインデックスが遅延
  • 1週間以上:インデックス削除リスク。順位が急落
  • 1ヶ月以上:ドメイン全体の評価低下。復旧後も回復に時間がかかる

Search Consoleの『カバレッジ → サーバーエラー(5xx)』で該当URLと件数を即確認できます。

緊急復旧手順(5分で開始)

ステップ1: サーバー稼働確認

サーバー管理画面にログイン → CPU・メモリ・ディスク使用率をチェック。100%近い項目があれば過負荷。

ステップ2: エラーログ確認

Apache: /var/log/httpd/error_log、Nginx: /var/log/nginx/error.log、PHP: /var/log/php-fpm/error.log を直近10分の記録で確認。

ステップ3: 直前の変更をロールバック

直前にデプロイ・プラグイン更新・設定変更があれば即座に元に戻す。WordPressならプラグイン全停止→1つずつ有効化で原因特定。

ステップ4: サーバー再起動

Apache/Nginxを再起動。VPSならsudo systemctl restart nginx、レンタルサーバーなら管理画面から再起動。

ステップ5: 復旧確認

httpstatus.ioやcurl -I で200応答を確認。Search Consoleの『URL検査』で再クロール依頼を送信。

ホスティング別の対処法

Cloudflare Pages

ダッシュボード → Overview → Deployments で最新デプロイのビルドログを確認。ビルド失敗が多い場合は前のバージョンにロールバック可能。

Vercel

Dashboard → Deployments → 該当デプロイ → Logs でサーバーレス関数のエラーを確認。Instant Rollback機能で前のバージョンに即座に戻せる。

CORESERVER / ロリポップ / Xserver

管理画面の『エラーログ』からリアルタイムで確認可能。PHP・MySQLのリソース制限を一時的に上げるオプションも。

さくらインターネット

コントロールパネルの『エラーログ』と『リソース情報』で確認。急激な負荷があれば一時的にBasic認証をかけて緩和。

再発防止策|サーバー監視と最適化

無料監視ツールの導入

  • UptimeRobot:5分間隔で死活監視・無料50サイトまで
  • Pingdom:高機能モニタリング(有料)
  • Cloudflare Analytics:トラフィック・エラー率可視化

定期メンテナンスルール

  • プラグイン・テーマはテスト環境で確認後に本番適用
  • データベースの最適化を月1回
  • サーバーリソースを週1回チェック
  • CDN(Cloudflare)でサーバー負荷を分散

Search Consoleでの検知

『カバレッジ → エラー』と『クロール統計情報 → サーバー応答時間』を週1回確認。異常があれば即調査。

よくある質問(FAQ)

Q. 一時的な5xxエラーで順位は下がりますか?

A. 数時間〜1日程度なら影響はほぼありません。Googleは5xxを『サーバー側の一時的な問題』と判断し、再クロールします。ただし24-48時間連続すると順位への影響が始まるので、長引く前に復旧させることが重要。

Q. 503エラーで『Retry-After』ヘッダーを設定すべき?

A. 長時間メンテナンスなら必須です。Retry-After: 3600のようにヘッダーを返すと、Googlebotは指定時間後に再アクセスし、順位への影響を最小化できます。短時間の障害なら不要。

Q. 原因が特定できない場合はどうすれば?

A. まずサーバー会社のサポートに連絡。レンタルサーバーなら電話・チャット窓口があります。クラウド系(Vercel・Cloudflare)はコミュニティフォーラムやステータスページも確認。

Q. 復旧後、Search Consoleで何をすべき?

A. (1)『カバレッジ』でエラー件数の推移を確認、(2)主要ページの『URL検査』でインデックス登録リクエスト、(3)『クロール統計情報』でクロール頻度の回復を確認。この3つを1週間ほど追跡。

Q. DDoS攻撃による503の対処法は?

A. Cloudflare等のCDN+WAFを導入するのが最強の対策。Cloudflare無料プランでも基本的なDDoS防御は機能します。既に導入済みなら『Under Attack Mode』を有効化で緊急防御可能。

まとめ

サーバー5xxエラーはSEOと売上の両方を脅かす緊急事態です。無料監視ツールの導入+Search Console定期チェック+迅速な復旧手順で、ダメージを最小化できます。
